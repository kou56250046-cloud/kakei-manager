# フォルダ投入だけで家計アプリへ自動反映する — 要件

関連する改善候補: `data--kakei-manager--4ea6f229`（writeJson が非アトミック）、
`data--kakei-manager--03bd7fd3`（close.js が build-web.js の失敗を握りつぶす）。
どちらも無人実行では影響が大きくなるため、本仕様の中で扱う。

## 背景

現状、毎月の反映は次の手順を踏んでいる。

1. `imports/` `給与明細/` `d-カード/` にファイルを置く
2. ターミナルを開いて `npm run close` を叩く
3. 分類が未確定の店（`needs_review`）を対話で確定する
4. `dist/index.html` を開いて確認する

このうち 2 と 3 が Claude Code との対話に依存している。パイプライン本体
（`npm run close -- --yes`）は既に非対話で通り、3 つのインポータはいずれも
「フォルダ内の全ファイルを毎回読み、既存 `id` と照合して重複を捨てる」冪等な
作りになっている。つまり**足りないのは、起動のきっかけ・結果の知らせ方・
新規店を確定する場所の 3 つだけ**である。

ファイルを置いた時点で反映が終わっていれば、月次運用は「置く」「通知を見る」
「要確認があればダッシュボードで選ぶ」に縮む。

## 受入条件

- [ ] ウォッチャを起動した状態で `imports/` に CSV を 1 つ置くと、数秒後に自動で
      取込〜`dist/index.html` 生成までが走り、Windows のトースト通知が出る
- [ ] `給与明細/` に PDF を置いたとき、`d-カード/` に .txt を置いたときも同様に走る
- [ ] 同時に複数ファイルを置いても、パイプラインの実行は 1 回にまとまる（デバウンス）
- [ ] コピー途中のファイルを掴んで壊れたまま取り込むことがない（サイズが安定するまで待つ）
- [ ] パイプライン実行中に新しいファイルが置かれた場合、実行が二重に走らず、
      完了後にもう一度だけ走る
- [ ] 通知に「新規取込 N件 / 要確認 N件」が出る。検算不一致があればその旨も出る
- [ ] パイプラインが失敗したとき、失敗したことが通知で分かる（黙って終わらない）
- [ ] `npm run panel` でローカルサーバが起動し、ブラウザで要確認の一覧が見える
- [ ] 要確認の 1 件について「店名ルールにする」を選びカテゴリを指定すると、
      `data/category_rules.json` にルールが追記され、既存データに反映され、
      `dist/index.html` が再生成される
- [ ] 要確認の 1 件について「この取引だけ確定」を選ぶと、該当取引に
      `manual_override: true` が付き、`npm run review -- --all` でも上書きされない
- [ ] ローカルサーバは 127.0.0.1 にのみ bind し、LAN の他端末からは接続できない
- [ ] ウォッチャを Windows のスタートアップに登録する手順が README にあり、
      登録後に PC を再起動してもウォッチャが動いている
- [ ] ウォッチャが動いていない状態でも、従来どおり `npm run close` で同じことができる
- [ ] 実行の履歴（日時・所要秒・取込件数・要確認件数・成否）が
      `data/watch_log.json` に追記される
- [ ] **ウォッチャ稼働中に `npm run close` を叩くと、二重に書き込まずに中止する**
      （`--force` を付けたときだけ従来どおり動く）
- [ ] **ウォッチャ稼働中に `npm run panel` を叩くと、既に開いている URL を案内して終了する**
- [ ] `npm run watch:status` で「タスクが登録されているか」と
      「ウォッチャが今生きているか（最終鼓動からの経過）」の両方が分かる
- [ ] ウォッチャが異常終了しても、タスクスケジューラが自動で立て直す

## 非目標

- **既存の `npm run close`（対話版）を置き換えない。** 自動化が壊れたときの
  逃げ道として残す。ウォッチャは close の対話部分を持たない
- **口座残高の入力は自動化しない。** ネットバンキングを見ないと分からないため、
  通知とダッシュボードの警告で促すに留める
- **未知の店を機械的に推測して分類しない。** 部分一致や類似度による自動分類は
  静かに誤分類が混ざるため行わない。要確認のまま残し、人が選ぶ
- **`docs/index.html`（GitHub Pages 公開版）からは書き戻せるようにしない。**
  確定パネルはローカル（127.0.0.1）専用とする
- **git commit / push は自動化しない。** 現行の「コミットは指示されたときだけ」を守る
- **ファイルの自動移動・リネーム・削除をしない。** 投入したファイルはその場に残す
  （インポータが冪等なので移動する必要がない）
- **Windows 以外の OS に対応しない。** 通知とスタートアップ登録が Windows 依存になる
- **クラウド同期・スマホからの投入には対応しない**
- **PWA（`docs/`）側の UI には手を入れない**
- **ウォッチャを見張る常駐プロセスは作らない。** 生存確認はタスクスケジューラの
  自動再起動と `npm run watch:status`、およびダッシュボードに出す「最後の自動反映」日時で足りる。
  監視の監視を作り始めると際限がない
- **複数人・複数端末での同時利用を想定しない。** 排他は「同じ PC 上で 2 つ走らない」までとする

## 制約

- **依存パッケージゼロ。** `npm install` を行わない。Node.js の標準モジュールと
  PowerShell の標準機能だけで実現する
- **外部通信ゼロ。** 家計データを外部サービスへ送らない
- 金額は整数（円）で扱う
- 口座番号・名義人は保存しない（`parse-meisai.js` の読み捨てを変更しない）
- 検算は行うが、不一致でも中止しない（警告して続行）
- `ui/` 配下のコードは `docs/index.html` に平文で載るため、
  **実際の金額・店名・口座名をコメントに書かない**
- `data/` に新しいファイル（`watch_log.json`）を足すため、
  `build-web.js` の `backup` 対象にも追加する
