# 公開版（docs/）の自動コミット・プッシュ — 要件

関連する改善候補: なし（台帳に該当する draft は無い）。

## 背景

常駐ウォッチャ（`scripts/watch.js`）と確定パネルは、取り込み〜`docs/index.html` の
生成までを自動で行う。しかしコミットとプッシュは手作業のまま残っているため、
**GitHub Pages の公開版は、人が `git push` するまで古いまま**になる。

実際に 2026-09-17 の給与明細はローカルでは反映済みだったのに、公開版は 9/15 の状態で
止まっていた。スマホで見るのは公開版なので、「置けば反映される」という自動化の
約束が、いちばん見る画面で守られていない。

もう一つの理由がバックアップ。`docs/index.html` は `data/` の唯一のバックアップであり、
**プッシュされるまではローカル PC と同じ場所にしか無い**。PC が壊れると、
最後のプッシュ以降の分は `npm run restore` で戻せない。

以前の自動取込仕様（`.claude/specs/auto-ingest/requirements.md`）は
「git commit / push は自動化しない」を非目標にしていた。本仕様はそれを、
**本人の依頼にもとづき `docs/` に限って**改める。

## 外部へ送信するもの

`origin`（GitHub の public リポジトリ `main`）へ、次のものだけを送る。

- 許可リストの `docs/` 生成物: `index.html` / `sw.js` / `manifest.webmanifest` /
  `icon-192.png` / `icon-512.png` / `apple-touch-icon.png`
- それらを含むコミット（メッセージは定型文のみ、作者は既存の git 設定）

**上記以外のパスを変えたコミットが未プッシュで残っているときは、何も送らない。**

## 受入条件

### 公開される
- [ ] ウォッチャ稼働中に `imports/` などへファイルを置き、取り込み〜`build-web.js` が
      成功すると、`docs/` の生成物が自動でコミットされ `origin/main` にプッシュされる
      （`git log origin/main -1 --format=%s` で確認できる）
- [ ] 確定パネルで分類または残高を確定したときも、同様にコミット・プッシュされる。
      **最後の確定から60秒**何も確定されなければ、それまでの確定をまとめて1コミットにする
- [ ] 許可リストのファイルに差分が無ければコミットしない（空コミットを作らない）

### 漏らさない
- [ ] コミットに入るのは許可リストのファイルだけ。作業ツリーに `scripts/` などの
      未コミットの変更やステージ済みの変更があっても、巻き込まれない
- [ ] `origin/main..HEAD` に**許可リスト以外のパスを変えたコミットが1つでもあれば、
      プッシュしない**（`blocked`）。トーストで知らせる
- [ ] 平文混入チェックに落ちた `docs/index.html` は作業ツリーに残らない
      （`build-web.js` は点検を通ってから書き出す）。したがって後の publish が拾うこともない
- [ ] コミットメッセージに金額・件数・店名・ファイル名（氏名を含む）を入れない。
      定型文（「自動反映（取込）」など）のみ
- [ ] 取り込みまたはビルドが失敗した回は、コミットもプッシュもしない
- [ ] 現在のブランチが `main` でないときは、コミットもプッシュもしない（`not_main`）

### 失敗しても止まらない
- [ ] プッシュが失敗したとき（ネットワーク断・認証切れ・リモートが先行など）、
      トーストで分かる。取り込みとビルドの結果は成功のまま扱う
- [ ] プッシュが失敗してもローカルのコミットは残り、次の publish（自動反映・パネルの確定・
      ウォッチャ起動時）でまとめてプッシュされる
- [ ] git が認証ダイアログなどの対話を求めても止まり続けない。対話を禁止し、
      **git の呼び出し1回ごとに90秒**で打ち切って `push_failed` / `commit_failed` にする
- [ ] **パネルの確定を断るのは、publish のコミット区間（`git add` 〜 `git commit`）の間だけ。**
      プッシュ中は断らない。プッシュ中も鼓動とパネルの応答は止まらない

### 記録と切り替え
- [ ] ウォッチャの取り込み実行のエントリ（`data/watch_log.json`）に公開の結果 `publish` が記録される。
      取り込み・ビルドが失敗した回は `skipped`
- [ ] パネル経由と起動時の publish の結果は `data/watch.out.log`（コンソール出力）に1行残る。
      失敗はトーストでも出る
- [ ] `config.json` の `publish.auto_push` を `false` にすると、コミットもプッシュもしない（ウォッチャ経路を含む）
- [ ] `npm run close`（対話版）の動作は変わらない（`scripts/close.js` に差分が無い）

## 非目標

- **`git pull` / rebase / merge は自動で行わない。** リモートが先行していたら
  プッシュ失敗として通知し、人が解決する。自動で統合すると衝突時に作業ツリーを壊す
- **`docs/` 以外のコミット・プッシュはしない。** 人のコミットが未プッシュで残っていれば
  自動公開自体を見送る（`blocked`）。それを勝手に出すことも、分けて出すこともしない
- **`npm run close -- --commit` は変更しない。** close は自動化が壊れたときの逃げ道
- **プッシュ失敗の定期リトライ（タイマー）は作らない。** 次の publish か再起動で拾えば足りる
- **GitHub Pages のデプロイ完了は確認しない。** プッシュが通れば成功とする
- **`main` 以外のブランチ、`origin` 以外のリモートには対応しない**
- **パネル単体起動（`npm run panel`）の終了時に、待機中の60秒分を急いで流さない。** 次の publish で拾われる
- **watch_log.json にパネル経由・起動時の publish のエントリは作らない。**
  watch_log は取り込み実行の履歴であり、種類の違う記録を混ぜない

## 制約

- 依存パッケージは増やさない（`node:child_process` の `spawn` で `git` を呼ぶ）
- リポジトリは public。送信するのは「外部へ送信するもの」に書いたものだけ
- ウォッチャの `running`（パネルに 409 を返す判定）は**取り込み〜ビルド〜コミットの間だけ**真にする。
  プッシュはその外で走らせる。`.watch.lock` の排他は変えない
- 通知の日本語は既存の `notify()` を通す（PowerShell スクリプトに埋め込まない）
